# Channel Alignment

Configured for **Clief Notes** (https://www.skool.com/cliefnotes).

## Content Pillars

| Pillar | Description | Audience Fit |
|--------|-------------|--------------|
| ICM / Folder Architecture Foundation | Core concepts: five-layer context hierarchy, `CLAUDE.md` + `CONTEXT.md` patterns, folder structure as agent architecture | Gives new members a shared vocabulary and a place to start before they build |
| Competition Workspaces | Biweekly comps (translators, auditors, cartographers, and similar) as shippable folder deliverables with locked contracts | Matches how members already ship — drop-in folders with clear input/output shapes |
| Context Engineering & Stage Contracts | Inputs tables, checkpoints, audits, and edit surfaces between stages | Helps builders move from vibes to inspectable, repeatable pipelines |
| Community Templates & Showcases | Member-built workspaces others can fork, reuse, and adapt to their domains | Turns peer work into portable assets instead of one-off demos |
| Research & Thesis Validation | ICM/MWP themes: folder structure replacing framework orchestration for sequential, human-reviewed workflows | Gives research-minded members a through-line from practice back to the thesis |

## Target Audience

- **Primary audience:** AI-curious builders, developers, and technical creators in Clief Notes who use (or want to use) Claude Code / Claude projects
- **What they care about:** Portable folder workspaces, clear stage contracts, competitions they can actually ship, and workflows that cut token waste and surprise
- **What they already know:** Programming skill varies; most are newer to ICM/MWP and context engineering than to general AI tooling
- **What makes them engage:** Concrete competition briefs, forkable templates, demos they can run the same day, and peer showcases

## Strategic Goals

- **Channel mission:** Give builders the cliff notes on the new AI age by teaching Interpretable Context Methodology (ICM / MWP) — folder structure as agent architecture — through the Skool course, biweekly competitions, and shared drop-in workspaces
- **Research thesis:** The MWP/ICM methodology — folder structure as agent architecture — replaces framework-level orchestration for sequential, human-reviewed workflows
- **Community value:** Delivering working MWP workspaces to community members solves their problems AND demonstrates the thesis
- **Content flywheel:** Every workspace built generates content (build process → demo → use-case story → research validation)
- **Current community need:** Members want ICM applied to their own domains but need working, well-contracted folder templates they can run and customize — not more theory alone
- **Community domains:** software development, content creation, consulting, education, research, marketing, operations, sales/support workflows

## Alignment Test

When evaluating whether an idea aligns with the channel, ask:

1. **Does delivering this generate content?** — The build process, the demo, or the community response should be filmable or writable
2. **Does it reinforce the thesis?** — Ideally it demonstrates that MWP works for a new domain. If not MWP-fit, does it at least relate to AI workflows, context engineering, or agent architecture?
3. **Does the audience care?** — Would Clief Notes members watch a walkthrough, enter a related competition, or fork this workspace?
4. **Is it shareable?** — Would someone who received this workspace share it or recommend it inside the community?
